MỤC LỤC



0. Cách sử dụng tài liệu này
Tài liệu này là đặc tả phần mềm hoàn chỉnh (software specification) để Claude Code xây dựng ứng dụng AISRM1 – AI-ResearchHub, hệ thống quản lý hoạt động khoa học và công nghệ (KH&CN) dành cho Phòng Quản lý khoa học của cơ sở giáo dục đại học/viện nghiên cứu.
Tài liệu gồm 10 phần (A–J). Phần nghiệp vụ viết bằng tiếng Việt; các thuật ngữ kỹ thuật, tên bảng dữ liệu, API, trường (field), prompt mẫu và mã nguồn giữ nguyên tiếng Anh để Claude Code triển khai chính xác và nhất quán.
Cách dùng được khuyến nghị: tạo repository GitHub tên aisrm1, chép nội dung tài liệu này vào thư mục docs/ (có thể tách thành các file con như gợi ý ở Phần J), rồi dùng prompt khởi đầu ở Phần J để Claude Code dựng khung dự án và build theo từng epic, triển khai lên Google Cloud Run.
Nguyên tắc cốt lõi: AI hỗ trợ — con người quyết định (human-in-the-loop). Mọi nội dung AI tạo ra (gợi ý phản biện, cảnh báo trùng lặp, chấm điểm công trình, dự thảo báo cáo...) đều ở trạng thái “gợi ý”, phải được người có thẩm quyền kiểm tra và phê duyệt trước khi dùng chính thức. AI luôn trích dẫn nguồn dữ liệu và không tự tạo số liệu khi hệ thống chưa có dữ liệu.

A. Tổng quan sản phẩm (Product Requirements)
A.1. Giới thiệu & bối cảnh
AISRM1 – AI-ResearchHub là hệ thống web hỗ trợ Phòng Quản lý khoa học và toàn bộ cộng đồng nghiên cứu của nhà trường quản lý vòng đời hoạt động KH&CN: từ thông báo và đăng ký đề tài, xét chọn, ký hợp đồng, triển khai, quản lý kinh phí, nghiệm thu, đến quản lý công bố khoa học, sở hữu trí tuệ, hội thảo, hợp tác và thống kê báo cáo.
Điểm khác biệt cốt lõi: AISRM1 không chỉ là phần mềm quản lý hồ sơ hành chính, mà là nền tảng “quản trị khoa học dựa trên dữ liệu và AI”. AI được tích hợp để trích xuất dữ liệu công bố, phát hiện trùng lặp thuyết minh, gợi ý phản biện theo chuyên môn, phân tích trắc lượng khoa học, kiểm tra liêm chính học thuật, dự thảo báo cáo thống kê và hỏi đáp trên kho dữ liệu KH&CN.
A.2. Mục tiêu sản phẩm
Nền tảng dữ liệu KH&CN tập trung: quản lý thống nhất hồ sơ nhà khoa học, đề tài/dự án, công bố, SHTT, hội thảo, kinh phí và hợp tác — một nguồn dữ liệu xác thực (single source of truth).
Số hóa quy trình quản lý KH&CN: số hóa toàn bộ luồng nghiệp vụ từ đăng ký, xét chọn, hợp đồng, tiến độ, nghiệm thu đến thanh quyết toán và lưu trữ.
Minh bạch & liêm chính: công khai quy trình hội đồng, kiểm soát xung đột lợi ích, phát hiện đạo văn/trùng lặp, quản lý đạo đức nghiên cứu.
Ứng dụng AI có kiểm soát: tự động hóa tác vụ lặp lại, hỗ trợ phân tích, gợi ý và cảnh báo, dưới sự phê duyệt của con người.
Hỗ trợ ra quyết định & KPI: cung cấp dashboard, trắc lượng khoa học và thống kê phục vụ lãnh đạo điều hành và báo cáo cấp trên (Bộ KH&CN, Bộ GD&ĐT).

A.4. Phạm vi & nguyên tắc thiết kế
Trong phạm vi (In-scope)
Quản lý hồ sơ nhà khoa học (researcher profile), nhóm nghiên cứu; tích hợp ORCID/Scopus.
Quản lý thông báo & đăng ký nhiệm vụ KH&CN (calls for proposals) và vòng đời đề tài/dự án.
Quản lý hội đồng khoa học: tuyển chọn, xét duyệt, nghiệm thu, phản biện; gợi ý phản biện bằng AI.
Quản lý kinh phí, hợp đồng, giải ngân, thanh quyết toán đề tài.
Quản lý công bố khoa học, tính điểm công trình, đối chiếu CSDL ngoài; quản lý SHTT.
Quản lý hội nghị/hội thảo, NCKH sinh viên, hợp tác & chuyển giao công nghệ.
Liêm chính học thuật: phát hiện trùng lặp/đạo văn, quản lý đạo đức nghiên cứu, xung đột lợi ích.
Khen thưởng, KPI nghiên cứu; báo cáo & thống kê KH&CN; dashboard.
Tính năng AI: trích xuất, tóm tắt, gợi ý phản biện, trắc lượng, cảnh báo, chatbot RAG, dự thảo báo cáo.
Phân quyền RBAC, audit log, quy trình phê duyệt cấu hình được.
Ngoài phạm vi (Out-of-scope) — phiên bản đầu
Hệ thống kế toán/tài chính tổng thể của trường — chỉ quản lý kinh phí KH&CN và đồng bộ dữ liệu.
Hệ thống quản lý đào tạo (LMS), nhân sự tổng thể — chỉ tích hợp dữ liệu liên quan.
Tạp chí khoa học điện tử (OJS) đầy đủ — chỉ quản lý công bố, có thể tích hợp sau.
Ứng dụng di động native (web responsive là đủ cho MVP).
Nguyên tắc thiết kế (Design Principles)
Human-in-the-loop: AI chỉ gợi ý; con người phê duyệt. Mọi đầu ra AI có trạng thái suggestion/draft.
Truy xuất nguồn gốc (traceability): mọi quyết định hội đồng, điểm số, cảnh báo AI đều liên kết tới nguồn và được lưu vết.
Cấu hình hóa: loại nhiệm vụ, quy trình xét chọn/nghiệm thu, công thức tính điểm công trình, vai trò phải cấu hình được, không hard-code.
Phân tách lưu trữ: file gốc, metadata và dữ liệu AI lưu ở 3 lớp riêng (xem Phần B.4).
Liêm chính & bảo mật: kiểm soát xung đột lợi ích trong hội đồng; AI tuân thủ đúng quyền của người dùng.
MVP trước, mở rộng sau: không over-engineer; ưu tiên kiến trúc sạch, dễ bảo trì, mở rộng dần.

B. Kiến trúc & công nghệ (Architecture & Tech Stack)
B.1. Tech stack đề xuất
Stack được chọn để Claude Code build nhanh, test cục bộ bằng Docker, và triển khai trọn vẹn trên Google Cloud cho production. Ưu tiên công cụ phổ biến, tài liệu phong phú, phù hợp xử lý tài liệu, đối chiếu CSDL khoa học và AI.
Lớp
Công nghệ đề xuất
Lý do chọn
Frontend
Next.js 14 (App Router) + TypeScript + Tailwind CSS + shadcn/ui + TanStack Query
UI dashboard/bảng/biểu mẫu hồ sơ KH&CN nhanh, hiện đại, SSR/CSR linh hoạt.
Backend
FastAPI (Python 3.11+) + Pydantic v2 + SQLAlchemy 2.0 + Alembic
Python thuận lợi cho xử lý tài liệu, trắc lượng, AI; FastAPI nhanh, type-safe, tự sinh OpenAPI.
Database
Cloud SQL for PostgreSQL 16 + pgvector
Dữ liệu nghiệp vụ quan hệ + vector embedding cho RAG trong một DB; managed, có PITR.
File storage
Google Cloud Storage (prod) / MinIO hoặc local FS (dev)
Object storage cho thuyết minh, hợp đồng, sản phẩm, bài báo PDF; tách khỏi DB.
AI – LLM
Claude API (Anthropic) — Claude Sonnet cho phân tích, Claude Haiku cho tác vụ nhẹ (đổi được sang Vertex AI)
Chất lượng cao cho phân tích văn bản học thuật tiếng Việt/Anh.
AI – Embeddings
Mô hình embedding đa ngôn ngữ (Voyage AI multilingual / multilingual-e5 self-host)
Hỗ trợ tiếng Việt tốt cho semantic search & phát hiện trùng lặp thuyết minh.
Xử lý tài liệu
PyMuPDF, python-docx, openpyxl; Google Document AI / Tesseract (scan); GROBID (bóc tách metadata bài báo)
Trích xuất nội dung & metadata từ thuyết minh, hợp đồng, bài báo.
Tích hợp ngoài
Crossref API, OpenAlex/Scopus API, ORCID API
Đối chiếu công bố, trắc lượng, định danh nhà khoa học.
Hàng đợi nền
Celery + Redis (dev) ; Cloud Tasks + Cloud Run Jobs (prod)
Xử lý nền: trích xuất, embedding, đối chiếu CSDL, kiểm tra trùng lặp.
Auth
JWT (access + refresh); tùy chọn Google Identity Platform/Firebase Auth (SSO, MFA)
MVP kiểm soát RBAC; nâng cấp SSO với tài khoản trường sau.
CI/CD
GitHub Actions → build Docker → Artifact Registry → Cloud Run
Tự động hóa kiểm thử & triển khai có kiểm soát theo nhánh.
Secrets
Google Secret Manager (prod) / file .env (dev)
Lưu khóa API (Claude, Scopus, ORCID), mật khẩu DB an toàn.
Quan sát hệ thống
Cloud Logging + Error Reporting + Cloud Monitoring
Theo dõi lỗi, hiệu năng, audit.
Lưu ý cho Claude Code: MVP chạy hoàn toàn bằng Docker Compose trên máy local (Postgres+pgvector + Redis + MinIO + backend + frontend). Phần Google Cloud kích hoạt khi deploy production. Dùng abstraction cho storage (StorageService), cho LLM (LLMProvider) và cho nguồn trắc lượng (BibliometricProvider: Crossref/OpenAlex/Scopus) để đổi nhà cung cấp mà không sửa nghiệp vụ.

B.4. Mô hình lưu trữ 3 lớp
Nguyên tắc bắt buộc: KHÔNG lưu file gốc trong cơ sở dữ liệu quan hệ. Hồ sơ KH&CN được quản lý theo ba lớp tách biệt:
Lớp
Lưu ở đâu
Nội dung
Lớp 1 — File gốc
Cloud Storage / MinIO
Thuyết minh, hợp đồng, báo cáo, sản phẩm, bài báo PDF, minh chứng tài chính, ảnh scan.
Lớp 2 — Metadata
PostgreSQL
Thông tin đề tài, công bố, hồ sơ nhà khoa học, kinh phí, trạng thái, phiên bản, checksum, storage_path.
Lớp 3 — Dữ liệu AI
PostgreSQL (chunks + embeddings/pgvector)
Text trích xuất, chunks, vector embedding, kết quả phân tích AI phục vụ tìm kiếm, trùng lặp & RAG.
Cấu trúc đường dẫn file đề xuất trên Object Storage

C.2. Mô tả chi tiết các phân hệ trọng tâm
M3 — Hồ sơ nhà khoa học (Researcher Profile)
Quản lý lý lịch khoa học của từng nhà khoa học: thông tin cá nhân, học hàm/học vị, chuyên ngành, hướng nghiên cứu, từ khóa chuyên môn, đề tài đã/đang chủ trì–tham gia, công bố, SHTT, giải thưởng.
Tích hợp ORCID để định danh; đồng bộ công bố từ Scopus/OpenAlex/Crossref (có xác nhận của người dùng).
Tự động tính các chỉ số trắc lượng: số công bố, tổng trích dẫn, h-index, i10-index (AI-8).
Hồ sơ chuyên môn (keywords + embedding) phục vụ gợi ý phản biện và tìm kiếm chuyên gia.
Trang hồ sơ công khai (tùy chọn) phục vụ kết nối hợp tác.
M6 — Quản lý đề tài / dự án (trọng tâm)
Quản lý toàn bộ vòng đời nhiệm vụ KH&CN các cấp (cơ sở, bộ/ngành, tỉnh, nhà nước, hợp tác/tài trợ). Hỗ trợ nhiều loại nhiệm vụ với biểu mẫu và quy trình cấu hình được.
Nộp thuyết minh trực tuyến theo biểu mẫu; quản lý phiên bản thuyết minh.
Quy trình xét chọn qua hội đồng (M7); ký hợp đồng và dự toán kinh phí (M8).
Quản lý tiến độ theo mốc (milestones), sản phẩm cam kết, báo cáo định kỳ.
Nghiệm thu: hội đồng nghiệm thu, biên bản, xếp loại, sản phẩm giao nộp, lưu trữ.
AI hỗ trợ: tóm tắt thuyết minh, phát hiện trùng lặp với đề tài đã có (AI-3), rà soát tính khả thi/ngân sách (AI-10), cảnh báo tiến độ (AI-11).
M7 — Hội đồng khoa học & gợi ý phản biện
Quản lý các loại hội đồng (tuyển chọn, xét duyệt thuyết minh, nghiệm thu) và quy trình phản biện. Hỗ trợ chấm điểm trực tuyến theo phiếu/tiêu chí, tổng hợp điểm, kết luận hội đồng.
AI gợi ý phản biện/thành viên hội đồng theo độ khớp chuyên môn (AI-4) — đối sánh embedding thuyết minh với hồ sơ chuyên gia.
Kiểm soát xung đột lợi ích: loại trừ người cùng đơn vị/đồng tác giả/người thân; cảnh báo tự động.
Phiếu nhận xét & chấm điểm số hóa; ẩn danh khi cần (blind review).
Tổng hợp kết quả, biên bản hội đồng, kết luận và kiến nghị.
M9 — Công bố khoa học & tính điểm công trình
Khai báo và quản lý công bố (bài báo ISI/Scopus, tạp chí trong nước, sách, kỷ yếu hội thảo). Đối chiếu với CSDL ngoài để xác thực chỉ số (IF, quartile, trích dẫn).
AI trích xuất metadata từ file/DOI (AI-2); đối chiếu Crossref/OpenAlex/Scopus (AI-14) để tự điền và xác thực.
Tính điểm công trình tự động theo công thức cấu hình được của trường (AI-16) — phân chia điểm theo đồng tác giả.
Liên kết công bố với đề tài, nhóm nghiên cứu, nhà khoa học và KPI.
Quy trình duyệt công bố để tính khen thưởng/KPI; chống khai trùng.
C.3. Vai trò & ma trận phân quyền (RBAC)
RBAC hai lớp: (1) vai trò hệ thống quy định khả năng tổng quát; (2) phạm vi theo đơn vị/đề tài (user scope) quy định người dùng thao tác trên dữ liệu nào. AI luôn tuân thủ đúng phạm vi quyền của người dùng.
Các vai trò hệ thống
Vai trò (role)
Mô tả & quyền tổng quát

Quản trị toàn hệ thống: cấu hình, người dùng, vai trò, biểu mẫu, công thức điểm, sao lưu.

EXTERNAL

C.4. Vòng đời đề tài & trạng thái
Mỗi đề tài/dự án đi qua vòng đời được kiểm soát chặt, mỗi bước có người chịu trách nhiệm và lưu vết:
Draft → Submitted → UnderReview → Approved → Contracted → InProgress
   │         │            │            │           │            │
 nháp     đã nộp      hội đồng       được       ký hợp       đang
 thuyết   thuyết     xét chọn      phê duyệt    đồng+        thực hiện
 minh     minh                                  dự toán
                                                              │
   Extended ◀── (gia hạn)                                     ▼
   Stopped  ◀── (dừng/thu hồi)        Accepted ◀── Acceptance(nghiệm thu) ◀── Reporting
                                          │
                                          ▼
                                      Liquidated (thanh lý) → Archived (lưu trữ)
Trạng thái
Ý nghĩa
Draft / Submitted
Chủ nhiệm soạn & nộp thuyết minh trong đợt xét.
UnderReview
Hội đồng tuyển chọn/xét duyệt đang đánh giá (có phản biện).
Approved
Được phê duyệt cấp kinh phí, chờ ký hợp đồng.
Contracted
Đã ký hợp đồng & duyệt dự toán; phân bổ kinh phí.
InProgress / Reporting
Đang triển khai; nộp báo cáo định kỳ theo mốc.
Acceptance / Accepted
Hội đồng nghiệm thu đánh giá; đạt → Accepted, kèm xếp loại.
Extended / Stopped
Gia hạn có phê duyệt / dừng – thu hồi khi vi phạm hoặc bất khả thi.
Liquidated / Archived
Thanh lý hợp đồng, quyết toán xong; lưu trữ hồ sơ.
C.5. Quy trình nghiệp vụ tổng quát (end-to-end)
Phòng QLKH ra thông báo & mở đợt đăng ký nhiệm vụ KH&CN (cấu hình biểu mẫu, tiêu chí, hạn nộp).
Nhà khoa học nộp thuyết minh trực tuyến; AI tóm tắt, phân loại lĩnh vực, kiểm tra trùng lặp.
Phòng QLKH thành lập hội đồng; AI gợi ý phản biện theo chuyên môn, loại trừ xung đột lợi ích.
Hội đồng tuyển chọn/xét duyệt chấm điểm trực tuyến; tổng hợp kết quả, ra kết luận.
Phê duyệt danh mục, ký hợp đồng, duyệt dự toán & phân bổ kinh phí (phối hợp Tài chính).
Triển khai: theo dõi mốc tiến độ, báo cáo định kỳ, giải ngân theo đợt; AI cảnh báo chậm tiến độ.
Nghiệm thu: hội đồng nghiệm thu đánh giá sản phẩm, xếp loại; lưu biên bản & sản phẩm.
Khai báo công bố/SHTT phát sinh; tính điểm công trình, KPI, khen thưởng.
Thanh lý, quyết toán; tổng hợp thống kê KH&CN; lưu trữ & phục vụ chu kỳ sau.

D. Lược đồ cơ sở dữ liệu (Database Schema)
PostgreSQL 16 + pgvector. Quy ước: tên bảng số nhiều, snake_case; mỗi bảng có id (UUID, khóa chính), created_at, updated_at; xóa mềm bằng deleted_at khi cần. Khóa ngoại đặt tên <entity>_id. Dùng Alembic cho migration.

F. Đặc tả tính năng AI (AI Features Specification)
F.1. Quan điểm & nguyên tắc tích hợp AI
AI là trợ lý chuyên môn cho công tác quản lý khoa học — hỗ trợ trích xuất, phân tích, gợi ý, cảnh báo và tự động hóa tác vụ lặp lại. AI KHÔNG thay thế hội đồng khoa học, phản biện hay cán bộ quản lý trong các quyết định chuyên môn.
Hỗ trợ ra quyết định, không tự động quyết định thay con người (đặc biệt trong xét chọn, nghiệm thu).
Gợi ý dựa trên dữ liệu thực — không trả lời chung chung, không bịa số liệu/trích dẫn.
Luôn trích nguồn (DOI, hồ sơ, văn bản) khi đưa ra kết luận.
Tuân thủ phân quyền: chỉ dùng dữ liệu trong phạm vi quyền của người dùng; bảo vệ dữ liệu cá nhân.
Kiểm soát xung đột lợi ích khi gợi ý phản biện.
Lưu lịch sử prompt, kết quả, người dùng kết quả và thời điểm (audit AI).
Mọi đầu ra AI ở trạng thái “gợi ý”; người có thẩm quyền chấp nhận/sửa/từ chối.

F.5. RAG & pipeline phát hiện trùng lặp
Tài liệu/đề tài/công bố upload
  → Trích xuất text & metadata (PyMuPDF/GROBID/python-docx, OCR nếu scan)
  → Chuẩn hóa, gắn lĩnh vực & ngôn ngữ
  → Chia nhỏ thành chunks → tạo embedding (đa ngôn ngữ) → lưu pgvector
  ┌─────────────────────────────┬──────────────────────────────────────┐
  │  RAG hỏi đáp                │  Phát hiện trùng lặp (AI-3/AI-9)      │
  │  - lọc theo phân quyền      │  - so khớp vector thuyết minh mới     │
  │  - truy hồi top-k chunk     │    với kho đề tài/công bố đã có       │
  │  - LLM trả lời + trích nguồn│  - chấm similarity_score + đoạn khớp  │
  └─────────────────────────────┴──────────────────────────────────────┘
Ràng buộc: Chatbot chỉ trả lời dựa trên dữ liệu được phân quyền cho người dùng; nếu không tìm thấy nguồn nội bộ, AI nói “chưa tìm thấy dữ liệu” thay vì bịa. Cảnh báo trùng lặp là gợi ý — hội đồng/cán bộ quyết định cuối cùng.

I. Triển khai trên Google Cloud (Deployment & DevOps)
I.1. Môi trường phát triển (local, Docker-first)
Toàn bộ MVP chạy được trên máy local bằng Docker Compose, không phụ thuộc Google Cloud. Đây là môi trường Claude Code dùng để build & test.
# infra/docker-compose.yml  (dịch vụ)
services:
  db:        postgres:16  (+ pgvector)   port 5432
  redis:     redis:7                      port 6379
  minio:     minio (S3-compatible)        port 9000/9001
  api:       build apps/api  (FastAPI)    port 8000
  worker:    build apps/api  (Celery worker)
  web:       build apps/web  (Next.js)    port 3000
 
# Khởi động
docker compose up --build
docker compose exec api alembic upgrade head
docker compose exec api python -m app.db.seed   # seed loại nhiệm vụ, đơn vị, demo
Biến môi trường (.env): DATABASE_URL, REDIS_URL, STORAGE_BACKEND (minio|gcs), GCS_BUCKET, ANTHROPIC_API_KEY, EMBEDDING_PROVIDER, CROSSREF_MAILTO, OPENALEX_KEY, SCOPUS_API_KEY, ORCID_CLIENT_ID/SECRET, JWT_SECRET. Dev dùng .env; prod dùng Secret Manager.

I.3. CI/CD (GitHub Actions → Cloud Run)
GitHub repo (nhánh)
  ├── feature/*  → CI: lint + test (pytest, vitest)
  ├── dev        → deploy môi trường dev
  ├── staging    → deploy môi trường thử nghiệm
  └── main       → deploy production (cần review + approve)
 
Luồng deploy:
  push → GitHub Actions → build Docker → Artifact Registry
       → deploy Cloud Run (api, web, worker)
       → kết nối Cloud SQL + Cloud Storage + Secret Manager
       → chạy alembic migrate (Cloud Run Job)
Nguyên tắc an toàn: KHÔNG để Claude Code tự push thẳng vào main hay tự deploy production. Claude Code hỗ trợ viết code/test/migration/PR; quyết định merge & deploy do con người kiểm soát. Dùng nhánh và Pull Request.
I.4. Những điều KHÔNG nên làm
Không lưu file gốc (PDF/DOCX) trong DB — dùng Cloud Storage; DB chỉ giữ metadata + vector.
Không build monolith quá lớn — bắt đầu modular monolith, tách worker AI/đối chiếu CSDL khi cần.
Không để AI tự quyết định xét chọn/nghiệm thu/khen thưởng.
Không gọi CSDL ngoài (Scopus/Crossref) đồng bộ trong request — luôn chạy nền & cache.
Không bỏ qua kiểm soát xung đột lợi ích khi phân công phản biện.
Không đưa dữ liệu cá nhân/nhạy cảm vào AI khi chưa có chính sách bảo mật, phân quyền & audit.

J.5. Prompt khởi đầu cho Claude Code
You are building AISRM1 (AI-ResearchHub), an AI-integrated Scientific Research
Management System for a university Research Management Office. The full
specification is in docs/ (read it first: database schema, API spec, AI features,
deployment). Target: run on Google Cloud (Cloud Run + Cloud SQL + Cloud Storage).
 
Build an MVP web application with this stack:
- Frontend: Next.js 14 (App Router) + TypeScript + Tailwind + shadcn/ui
- Backend: FastAPI (Python 3.11) + SQLAlchemy 2.0 + Alembic + Pydantic v2
- Database: PostgreSQL 16 + pgvector (Cloud SQL in prod)
- File storage: abstraction (MinIO for dev, Google Cloud Storage for prod)
- Background jobs: Celery + Redis (dev) / Cloud Run Jobs + Cloud Tasks (prod)
- AI provider: Claude API (behind an LLMProvider interface)
- Bibliometrics: Crossref + OpenAlex (behind a BibliometricProvider interface)
- Local dev: Docker Compose; Deployment target: Google Cloud Run
 
Core MVP modules (build incrementally, one epic at a time, with tests):
1. Auth + role-based access control (system roles + unit/project scope)
2. Researcher profiles (+ ORCID sync) and organization
3. Calls for proposals (dynamic forms) and proposal submission
4. Project lifecycle management (state machine)
5. Scientific councils and online review/scoring (with conflict-of-interest)
6. Funding, contracts and disbursements (basic)
7. Publications + DOI verification (Crossref/OpenAlex) + work scoring
8. AI document summarization + proposal similarity detection (RAG pipeline)
9. S&T statistics reporting and dashboard
10. Audit log + approval workflow
 
Rules:
- Human-in-the-loop: all AI output is a SUGGESTION, never auto-approved. AI must
  NOT decide proposal selection, acceptance, or rewards.
- AI must cite sources (DOI, records, documents) and must NOT fabricate data.
- Enforce conflict-of-interest checks before assigning reviewers.
- Respect RBAC everywhere, including AI/RAG retrieval scope and personal data.
- Do not store original files in the relational DB (use object storage).
- Call external databases (Scopus/Crossref) only in background jobs, with caching.
- Start with a clean modular-monolith backend; do not over-engineer.
- Create repo structure, DB schema (Alembic migrations), backend API, frontend
  pages, seed data, and docs.
- Work on branches and open Pull Requests; never push to main or deploy
  production automatically.
 
Start with Epic E1 (Project Setup): scaffold the monorepo, docker-compose,
Postgres with pgvector, FastAPI skeleton with health check, Next.js skeleton,
and CI. Then stop and summarize before continuing to E2.
